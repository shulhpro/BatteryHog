# Техническое задание для Antigravity

## MacMemoryGuard — мониторинг памяти macOS

**Версия:** 1.1  
**Устройство:** MacBook Apple M3, 8 ГБ Unified Memory  
**Первый этап:** пассивный мониторинг в течение 72 часов фактической работы агента

### 1. Цель

Создать лёгкую локальную open-source утилиту, которая собирает историю использования оперативной памяти, предупреждает о длительном повышении давления памяти и выявляет приложения, коррелирующие с такими эпизодами. По итогам трёх дней сформировать отчёт и предложить правила последующей автоматизации.

**На первом этапе запрещены автоматическое закрытие, приостановка и принудительная очистка памяти.**

### 2. Исходная ситуация

- Использование RAM иногда отображается как ~99%.
- Swap Used наблюдался около 1,1 ГБ.
- Memory Pressure иногда жёлтый и возвращается в зелёную зону.
- Активные рабочие приложения — Gemini и Antigravity.
- `agy` — внутренний хаб Antigravity, запускаемый из Gemini; в момент диагностики слушал 127.0.0.1:53227. Порт и PID динамические, не использовать для постоянной идентификации.
- Защищать рабочие процессы и их дочерние компоненты; не суммировать без оговорок показания памяти разных процессов как независимое физическое потребление.

### 3. Реализация

Предпочтительно Swift с нативными API macOS, пользовательский `launchd` LaunchAgent, локальное хранение SQLite или JSONL, CLI. Без root, Docker, Electron, телеметрии и внешнего сервера. Перед реализацией проверить версию macOS и доступность API.

Собирать каждые ~15 секунд:

- Физическая, используемая, доступная и сжатая память.
- Swap Used и доступные показатели активности swap за интервал.
- События системного Memory Pressure и вспомогательные VM-метрики.
- Топ процессов по памяти, PID, PPID, имя, исполняемый файл, Bundle ID (где доступно), принадлежность приложению, активное/фоновое состояние.
- Время и динамику потребления каждого наблюдаемого приложения.

**Не выдавать расчётные категории за точное значение цвета графика Activity Monitor.** Если публичный API не предоставляет цвета, ввести собственные `NORMAL`, `WARNING`, `CRITICAL` с зафиксированной методикой и ограничениями.

### 4. Уведомления

Пороговые значения сделать конфигурируемыми; предварительные правила:

- Устойчивый `WARNING` более 3 минут — уведомление.
- Устойчивый `CRITICAL` более 60 секунд — срочное уведомление.
- Кратковременные колебания только логировать.
- Повтор для одного непрерывного эпизода не чаще раза в 15 минут, кроме существенного ухудшения.
- Фиксировать возврат к норме и полную длительность эпизода.

Указанные интервалы — стартовые гипотезы, подлежащие проверке на реальном устройстве. Одна лишь заполненность RAM или накопленный размер swap не являются достаточными триггерами.

### 5. Диагностика потребителей

Во время эпизодов нагрузки записывать топ-15 процессов и дополнительно агрегировать по приложениям, где корректна их идентификация. Сохранять динамику за 5, 15 и 60 минут, связь с родительским процессом, активность и предполагаемый вклад в рост давления памяти. Большой расход RAM сам по себе не доказывает утечку; маркировать постоянный рост только как *подозрение* и документировать основание.

Защищённые сущности: Gemini, Antigravity, `agy`, их обнаруженные дочерние процессы, WindowServer, kernel_task, launchd и другие системные процессы. На первом этапе их можно мониторить, но нельзя изменять их состояние.

### 6. Хранение, CLI, отчёты

Хранить данные не менее 72 часов; добавить ограничение объёма, ротацию, защиту от повреждённых записей, экспорт CSV/JSON. Предусмотреть команды:

```text
macmemoryguard status
macmemoryguard top
macmemoryguard monitor
macmemoryguard history
macmemoryguard report
macmemoryguard export
```

Итоговый Markdown-отчёт за 72 часа должен содержать:

- Фактическое время наблюдения и пропуски.
- Число, длительность и время эпизодов WARNING/CRITICAL.
- Динамику RAM, compressed memory и Swap, включая активность swap.
- Топ-20 приложений по памяти и динамике, с оговорками об общей памяти.
- Подозрения на утечки и степень уверенности.
- Какие приложения совпадали по времени с ухудшением давления.
- Предложения по будущему allowlist/denylist и безопасным правилам автоматизации.
- Явное разграничение измеренных фактов и предположений.

### 7. Проверка и критерии готовности

Добавить тесты сбора метрик, смены состояний, подавления повторных уведомлений, записи и экспорта, устойчивости после перезапуска и удаления LaunchAgent. Не генерировать искусственный критический дефицит памяти на рабочем Mac без отдельного разрешения.

MVP готов, когда мониторинг работает без повышенных привилегий, уведомления проверены, лог содержит измерения, режим исключительно пассивный и доступен воспроизводимый отчёт.

### 8. Порядок выполнения

1. Проверить среду и поддерживаемые API; оформить архитектурное решение.
2. Реализовать и протестировать режим **Observe**.
3. Установить LaunchAgent, проверить автозапуск и журналирование.
4. Запустить наблюдение на 72 часа *фактической работы агента*.
5. По завершении сформировать Markdown-отчёт и рекомендации.
6. **Не включать и не реализовывать как активный режим автоматическое закрытие процессов до отдельного решения пользователя после анализа данных.**

**Ожидаемый результат Antigravity:** исходный код, тесты, README, инструкция установки/удаления, безопасно работающий агент наблюдения и трёхдневный диагностический отчёт после накопления данных.
